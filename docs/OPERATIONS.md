# CDR Radio operations

## Deploy the frontend

Use a Cloudflare Workers Free account and a stable `workers.dev` hostname for this project. The supplied Wrangler configuration publishes static assets and falls back to the app for browser navigation. The existing Supabase project supplies Auth and Edge Functions. [Cloudflare SPA routing](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/) · [Static asset billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)

1. From the repository on Windows, use `npx.cmd wrangler@4.168.0 login` and approve Wrangler in the browser. Use `npx.cmd wrangler@4.168.0 whoami` to confirm the destination Workers Free account. Find its hostname in Workers & Pages under **Your subdomain**. Keep credentials in the browser or local credential store. Use the project's exact HTTPS origin as `RADIO_DEPLOYED_ORIGIN`, without a trailing slash. Keep `RADIO_HOSTED_PUBLISHABLE_KEY` in the ignored `.env.supabase-hosted.local`. [Wrangler OAuth](https://developers.cloudflare.com/workers/wrangler/commands/general/#login)
2. Run `npm run build:hosted`. Inspect `dist` for the production HTML, hashed assets and `listen-qr.svg`, and scan it against the configured provider key. Provision the public origin in the Supabase `RADIO_DEPLOYED_ORIGIN` secret. Keep `RADIO_WEB_ORIGIN` for the existing development client. Set Supabase Auth's Site URL to the final hostname and limit redirect allowlist entries to the intended URLs. Preserve existing approved development entries.
3. Configure the station daily target in `AZURACAST_DAILY_PLAYLIST_ID` and the recovery target in `AZURACAST_RECOVERY_PLAYLIST_ID` for both authenticated Edge Functions. Confirm the active fallback through provider read-back. Use the optional comma-separated `AZURACAST_PREVIEW_ONLY_MEDIA_IDS` for recording-specific permissions. Apply the repository migrations to the existing linked Supabase project before deploying the changed Edge Functions. With the final origin, verify station GET, authenticated function preflight, anonymous admin denial and rejection of an unrelated origin. Then deploy the static build with Wrangler 4.168.0 in the destination account.
4. Run `node scripts/check-public-player.mjs <origin> --metadata-only` to verify navigation, reload, QR, signed-out route protection and station metadata without starting audio. Remove `--metadata-only` when ready for the independent listening checks. Keep assessment accounts and passwords out of public artifacts.

The Cloudflare Workers Free release supports the limited schedule workflow described below. [Public application](https://cdr-branch-radio.abdalqaderfroukh1.workers.dev/) · [Branch player](https://cdr-branch-radio.abdalqaderfroukh1.workers.dev/listen) · [Readiness checklist](READINESS.md)

## Dashboard publication, editing and cancellation

1. Sign in to **البث اليومي**. **القائمة المفعّلة في المحطة** shows the verified provider order. The editor starts from that order until a dedicated working copy exists. A saved copy is identified separately from current station order. Use the station-order disclosure to restore that order to the editor. When its order differs, **مقارنة مع القائمة المفعّلة** shows both sequences and the added and removed tracks. **حفظ نسخة التحضير** saves only to the app. For a reorder of the existing members of the configured active daily playlist, select **مراجعة تحديث المحطة** then **تحديث ترتيب المحطة**. An exact match skips the provider write. The queue may still contain previously selected tracks after a change. [Verification scope](TEST_REPORT.md#november-25--daily-editor-screenshot-investigation)
2. Adding or removing tracks or switching back from the recovery fallback requires a station operator. The editor shows the handoff before **حفظ نسخة التحضير** and repeats it in **مراجعة نسخة التحضير**.
   - Open **Music Files** on Quintastream station 12. Wait for new media to process. Assign the intended tracks to **CDR daily - Ghammas Baladi (188)** and remove only the excluded tracks’ membership in 188. Preserve the underlying files and all other memberships.
   - In **Playlists**, set 188 to **General Rotation**, **Sequential**, with no schedule. Open **Reorder**, match the editor’s sequence and save in Quintastream. Verify the membership and order there.
   - For edits to active 188, keep it enabled. To switch back from 176, prepare 188 while disabled, then enable 188 and disable 176 in the same maintenance window. Finish with 188 as the sole enabled populated unscheduled General Rotation playlist. Keep 176 intact for recovery and 189 disabled for preview.
   - Return to the app, select **تحديث حالة المحطة**, and compare the provider playlist ID and ordered tracks with the prepared copy. Listen separately if the audible result needs verification. [Station 12 playlists](https://quintastream.cl/station/12/playlists) · [AzuraCast playlist settings](https://azuracast.com/docs/user-guide/playlists/)
3. In either editor, select **إضافة صوتيات**. Search or filter the library and select tracks in order. **رفع ملفات جديدة** accepts permitted MP3s up to 5 MiB each and appends each file after the provider confirms processing. Use **تحقّق مجددًا** after an uncertain upload. **الصوتيات** offers the same upload flow, search, categories, duration and local preview. Removing a track from a list leaves its file available.
4. Drag the row handle or focus it and press Space, Up or Down, then Space. The separate arrow buttons also move a track. **استماع تجريبي** plays on your device. **تراجع عن الإزالة** restores the last removed track before saving. If a save reports a newer revision, compare the newer order with your edits before choosing a version.
5. From **البرامج الخاصة**, select **إنشاء برنامج خاص**. Enter a name, Amman date and times. An earlier end time means the following day. Continue to **المقاطع ومراجعة النشر** and add at least two distinct eligible tracks. Use the shared picker to add a library file or copy all or selected tracks from a saved collection. **مراجعة النشر** checks the window and shows the order, repeat and intended return to daily. Confirm with **حفظ ونشر البرنامج**, or use **حفظ دون نشر** to finish later. A program must begin more than a minute ahead.
6. **قادم**, **ضمن موعده الآن**, **انتهى موعده** and **ملغى** describe the verified configuration and its window. Use **عرض البرامج** for completed and cancelled programs. To edit a future program, open **تحرير البرنامج** more than one minute before its published start. **حفظ دون نشر** keeps the current schedule armed. **مراجعة النشر** then applies the saved edits to the existing provider playlist after confirmation.
7. **إلغاء الجدولة** checks that the provider disabled the playlist and cleared its schedule and memberships. Two additional tracks played after confirmed active cancellation in a previous test. Use a future fixture for verification. After an uncertain response, use **تحقّق من حالة النشر** or **إعادة التحقق من المحطة**. A program write may hold its lease for 75 seconds. After an uncertain daily reorder, refresh station status before retrying. Whole-day, play-once, immediate interruption and stop remain planning options. Publication checks protected daily memberships, distinct recordings, authorization and file readiness. [Scheduling exceptions](PROVIDER_CONTRACT.md#provider-trace-request)
