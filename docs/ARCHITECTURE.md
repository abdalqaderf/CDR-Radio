# CDR Radio architecture

## Broadcast and administration

The browser loads an Arabic React application from Cloudflare Workers Static Assets with SPA routing. Cloudflare serves HTML, CSS, JavaScript and the listener QR on Workers Free. The build points to the existing Supabase Free project and includes its publishable key and the public frontend origin.

- The branch player obtains the station name, audio URL and current metadata from the public Supabase `station` function. The browser connects directly to the provider's Icecast MP3 mount for audio. Stop, mute and reconnect affect that browser's audio element.
- Admin login uses Supabase Auth. `admin-drafts` validates the bearer with Auth, then passes the same identity to PostgREST. PostgreSQL checks the admin allowlist and enforces draft revisions and time-window rules. `admin-media` verifies the caller through PostgREST and sends uploads to AzuraCast using a private credential. The same authorization protects bounded MP3 previews resolved by station media ID. The browser plays each preview from a local object URL.
- Mutable state lives in PostgreSQL. Saved lists preserve provider media IDs in order. Special programs preserve the Amman civil date and UTC instants. Saving an edit to a published program increments its revision and stores the proposed fields beside the verified publication. A service-only reservation checks the verified admin, revision, overlap and station mutation lease. The Edge Function creates or reconciles the provider playlist by program UUID, verifies it while disabled, enables it and reads the result back. Cancellation independently reads back disabled status, an empty schedule and no memberships before storing the receipt.
- The shared track editor uses handle-only pointer sorting, keyboard sorting and move buttons. Uploads use the authenticated media function and a stable per-file identity. A lost response is reconciled against the original stored path, exact size, authoritative media ID and duration before insertion. The daily editor resolves only `daily_editor_draft_id` or starts from the confirmed station order. The legacy `daily_draft_id` remains in workspace data for older clients. The first save locks the dedicated pointer. A service-only reservation checks authorization and the saved revision before the Edge Function can reorder the configured daily target when it is the sole verified active fallback. The function compares the reviewed and current orders, skips a write if they already match the saved order, or sends membership weights and checks the result by reading again. Membership changes and fallback switches use the station dashboard. [Provider contract](PROVIDER_CONTRACT.md)
- AzuraCast manages media, ordered playlists, the upcoming queue and dated playout. Icecast distributes the stream. The provider owns execution once a schedule is enabled. Daily fallback now uses playlist 188, with 176 preserved for recovery. Program publication protects configured daily and recovery memberships, checks media readiness and distinct recording identity, and enforces any recording-specific preview-only permissions. The Quran category is used for finding audio. Earlier two-track tests showed exclusive special playout and eventual fallback to 176. Extra special tracks started at closing and both one-track settings let daily audio into the special window.

The Edge Functions accept the configured development and deployment origins. Browser origin checks and bearer verification are separate controls. Provider and service credentials stay in server-side configuration. The public station response is limited to listener data.
